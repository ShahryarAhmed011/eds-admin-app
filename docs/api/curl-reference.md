# EDoorStep API — curl reference

Every endpoint the backend serves: **87 operations**, generated from the application's own OpenAPI schema by `scripts/gen_curl_docs.py`. Regenerate it after any route or request model change — do not edit this file by hand.

Base URL: **`https://api.edoorstep.com/api/v1`**

## Read this first

**Every response has the same shape.** The payload is under `data`; the machine-readable failure code is under `error.code`. Full contract in [api-response-envelope.md](api-response-envelope.md).

```json
{
  "success": true,
  "status": 200,
  "message": "Fetched successfully",
  "data": {
    "...": "the payload"
  },
  "meta": {
    "request_id": "req_01JXYZ",
    "timestamp": "2026-08-22T15:00:00.000Z",
    "version": "v1"
  },
  "pagination": {
    "limit": 20,
    "next_cursor": "eyJpZCI6…",
    "has_next": true
  }
}
```

```json
{
  "success": false,
  "status": 401,
  "message": "the email or password is not correct",
  "data": null,
  "error": {
    "code": "invalid_credentials"
  },
  "meta": {
    "request_id": "req_01JXYZ",
    "timestamp": "2026-08-22T15:00:00.000Z",
    "version": "v1"
  }
}
```

- Branch on `status` and `error.code`. **Never** parse `message` — it is reworded freely.
- `data` is `null` on every failure, so reading it is unconditional.
- Collections are always at `data.items`, even where the endpoint does not paginate.
- Paginated endpoints add `pagination`; pass `next_cursor` back as `cursor` and stop when `has_next` is false. `limit` max is 50.
- **There are no 204s.** Logout and deletes return `200` with `data: null`.
- Show `meta.request_id` on error screens — it is what makes a bug report traceable.
- Money is always an integer in **paisa**. `64500` renders as Rs 645. Never send floats.
- Roles are `customer`, `retailer`, `rider`, `admin`. The same email can hold one account per role, so `role` is required on register, login and OTP calls.
- In this environment the OTP code is always **`123456`** and no email is sent.

## Getting a token

Every command below marked *bearer* uses `$TOKEN`. Set it once in your shell, and it expires in about 15 minutes:

```bash
TOKEN=$(curl -s -X POST "https://api.edoorstep.com/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"Abcd-1234","role":"retailer"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["access_token"])')

echo "$TOKEN"   # if this is empty, the login failed — run it without the pipe to see why
```

Note the `["data"]` in that extraction: the token is at `data.access_token`, not at the top level. That is the single change most likely to break existing frontend code.

Endpoints whose route declares a one-line `summary=` show it next to the method; the rest are listed by path and body alone, which is a gap in the route definitions rather than in this document. Ask the backend for a description of any that are not self-evident.

## Authentication & session

### `POST /auth/login`

*public* — Exchange an email and password for a session

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "Abcd-1234",
    "role": "customer"
  }'
```

Returns in `data`: `access_token`, `token_type`, `expires_in`, `refresh_token`, `refresh_expires_in`, `role`, `user`

Errors: `401` invalid_credentials, `429` rate_limited, per IP and per email

### `POST /auth/logout`

*bearer* — Log out everywhere — ends every session, and takes a live shop offline

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/logout" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "refresh_token": "<REFRESH_TOKEN>"
  }'
```

The body is optional — the call is valid without `-d` at all.

Returns in `data`: `sessions_revoked`, `shop_paused`

### `POST /auth/otp/resend`

*public* — Send a fresh verification code, superseding the previous one

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/otp/resend" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "role": "customer"
  }'
```

Returns in `data`: `sent_to`, `expires_at`, `resend_available_at`, `length`

Errors: `429` rate_limited or otp_locked

### `POST /auth/otp/verify`

*public* — Exchange a verification code for a session

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/otp/verify" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "role": "customer",
    "code": "123456"
  }'
```

Returns in `data`: `access_token`, `token_type`, `expires_in`, `refresh_token`, `refresh_expires_in`, `role`, `user`

Errors: `401` otp_invalid, `410` otp_expired, `429` otp_locked

### `POST /auth/refresh`

*public* — Rotate a refresh token

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/refresh" \
  -H "Content-Type: application/json" \
  -d '{
    "refresh_token": "<REFRESH_TOKEN>"
  }'
```

Returns in `data`: `access_token`, `token_type`, `expires_in`, `refresh_token`, `refresh_expires_in`, `role`, `user`

Errors: `401` token_invalid, or token_reused

### `POST /auth/register`

*public* — Create a self-service account and send a verification code

```bash
curl -s -X POST "https://api.edoorstep.com/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Ali",
    "last_name": "Khan",
    "email": "user@example.com",
    "password": "Abcd-1234",
    "role": "customer",
    "phone_country_code": "+92",
    "phone_number": "3001234567"
  }'
```

Returns in `data`: `user_id`, `email`, `role`, `onboarding_status`, `username`, `otp`

Errors: `400` invalid_request, `409` email_in_use or phone_in_use, `429` rate_limited

### `POST /auth/signup`

*public* — Alias of /auth/register — the specification's name for it

